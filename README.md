# Open Weather Map

Консольное приложение на Python для получения текущей погоды через OpenWeather. Показывает температуру в °C и описание погоды на русском языке. Искать можно по названию города или координатам.

## Требования

- Python 3.10 или новее.
- Ключ API OpenWeather, указанный в переменной `API_KEY`.
- Интернет для получения свежих данных.

Зависимости: `requests` и `python-dotenv`. Для тестов используется встроенный модуль `unittest`.

## Установка и настройка

Команды ниже предназначены для терминала macOS/Linux. Сначала перейдите в папку проекта. Для текущего расположения на macOS:

```bash
cd /Users/vladislav/Projects/Open_Weather_Map
```

Создайте виртуальное окружение, если папки `venv` ещё нет:

```bash
python3 -m venv venv
```

Активируйте окружение и установите зависимости:

```bash
source venv/bin/activate
python -m pip install -r requirements.txt
```

`venv` хранит Python и зависимости проекта отдельно от других проектов. После активации в начале строки терминала обычно появляется `(venv)`. В новом окне терминала окружение нужно активировать снова.

Создайте файл `.env` в корне проекта или отредактируйте существующий, указав свой ключ OpenWeather:

```dotenv
API_KEY=ваш_ключ_OpenWeather
```

Замените значение после `=` настоящим ключом. Файл `.env` исключён из Git через `.gitignore`; не публикуйте ключ. Если `API_KEY` уже задана в окружении терминала, она имеет приоритет над значением в `.env`.

## Запуск

С активированным окружением:

```bash
python weather_app.py
```

Можно запустить и без активации, напрямую используя Python из `venv`:

```bash
./venv/bin/python weather_app.py
```

Программа показывает меню:

```text
1 — по городу
2 — по координатам
0 — выход
Выберите режим:
```

После результата или обработанной ошибки меню появляется снова. Для завершения выберите `0`. Команда `deactivate` в терминале отключает виртуальное окружение после выхода из программы.

### По городу

Выберите `1` и введите, например, `Москва` или `London`. Программа сначала получает координаты первого найденного города, затем запрашивает погоду для них.

Пример вывода с условными погодными данными:

```text
Выберите режим: 1
Введите город: Москва
Погода для Москва (55.75, 37.62): 12.5°C, ясно
```

Пустое название вызывает сообщение об ошибке. Если геокодинг не находит город, программа предлагает проверить название.

### По координатам

Выберите `2`, затем введите широту и долготу отдельно:

```text
Выберите режим: 2
Введите широту (−90…90): 55,75
Введите долготу (−180…180): 37.62
```

- Широта: от −90 до 90 включительно.
- Долгота: от −180 до 180 включительно.
- Дробную часть можно отделять точкой или запятой.

Некорректные числа и координаты вне диапазона отклоняются до запроса к API. Название места берётся из погодного ответа, если оно там есть; иначе выводятся координаты.

## Кэширование

После каждого успешного получения и проверки погоды приложение сохраняет `weather_cache.json` рядом с `weather_app.py`. Файл содержит один последний успешный ответ:

| Поле | Содержимое |
|---|---|
| `city` | Введённый город или название из погодного ответа; может быть пустой строкой при поиске по координатам |
| `lat` | Широта запроса |
| `lon` | Долгота запроса |
| `fetched_at` | Время получения ответа в ISO 8601, часовой пояс UTC |
| `weather` | Полный погодный ответ API |

При обычном запросе программа всегда обращается к API. Кэш используется как запасной вариант: после исчерпания повторов при временной недоступности API приложение предлагает показать сохранённые данные, если их возраст **строго меньше 3 часов**.

Перед подтверждением выводятся место и время сохранённого ответа. **Кэш может относиться к другому городу или координатам**, поскольку хранится только последний успешный результат.

```text
Показать эти данные из кэша? [д/Н]:
```

Для согласия введите `д`, `да`, `y` или `yes` без учёта регистра. Enter и любой другой ответ означают отказ. Если кэш отсутствует, повреждён или устарел, программа сообщает, что свежего кэша нет.

Неудачный запрос не заменяет предыдущий кэш. Ошибка записи кэша не мешает показать успешно полученную погоду. Файлы `weather_cache.json` и `weather_cache.json.tmp` исключены из Git.

## Повторы запросов

Программа повторяет запрос при тайм-ауте, ошибке соединения, обрыве передачи ответа, HTTP `429` и HTTP `500`, `502`, `503`, `504`.

После первой попытки выполняется **до 3 повторов** с паузами **1, 2 и 4 секунды** — максимум 4 попытки для каждого запроса. При успехе повторы прекращаются. Эта логика применяется отдельно к геокодингу и запросу погоды.

В `requests` задан `timeout=10`: он ограничивает ожидание соединения и чтения ответа, а не общее время всех попыток. Время запросов добавляется к паузам между повторами. Постоянного ограничения частоты успешных запросов нет.

Ошибки вроде HTTP `401`, неверного ввода или некорректного JSON не вызывают повторов и предложения кэша. При `401` проверьте значение `API_KEY` в `.env` или окружении терминала.

## Проверка работы

### Автоматические тесты

Из корня проекта с активированным `venv` выполните:

```bash
python -m unittest -v
```

Без активации окружения:

```bash
./venv/bin/python -m unittest -v
```

Тесты имитируют ответы API и задержки: интернет и настоящий ключ не нужны. Кэш создаётся во временной папке, пользовательский файл не изменяется.

Проверяются оба режима ввода, границы координат, сохранение кэша, срок его действия, повреждённый файл, согласие и отказ от кэша, повторы запросов и ошибки записи. Успешный запуск заканчивается строкой `OK`.

### Ручная проверка

| Действие | Ожидаемый результат |
|---|---|
| Выбрать `1`, ввести `Москва` | Температура и описание погоды; обновление кэша |
| Выбрать `2`, ввести `55,75` и `37.62` | Погода по координатам |
| Выбрать `1`, отправить пустой ввод | Сообщение о пустом названии |
| Выбрать `2`, ввести `91` и `0` | Сообщение о допустимых диапазонах |
| Ввести неизвестный пункт меню | Предложение ввести `1`, `2` или `0` |
| После успешного запроса отключить интернет и повторить запрос в течение 3 часов | До 3 повторов, затем предложение показать кэш |
| Выбрать `0` | Завершение программы |
